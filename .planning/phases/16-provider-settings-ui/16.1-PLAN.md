## Tasks

1. **Service**: new `apps/desktop/src/lib/services/providerSettings.ts` — svelte stores for DSP (command, mode live|file-backed, timeoutMs, frameCount) and JACK (command, timeoutMs, delegateMode foreground|detached, readyDelayMs), localStorage persistence under the legacy keys, derived readiness flags (`dspRestoreProviderReady`, `jackLiveProviderReady`, `jackRestoreProviderReady`) with the same validation as the old code (positive/non-negative integer text). Unit tests (pure logic; inject storage or guard localStorage).
2. **Runtime wiring**: runtime.ts consumes the readiness flags: DSP candidate appears in `backendCandidates` via `withDspProviderCandidate` port (available only when ready); `createHostAdapter` builds the DSP adapter when backend dsp+ready and passes `virtualPortProvider` to the JACK adapter when jack provider ready (incl. detached args); DSP live capability check (`verifyDspLiveProviderCapability`) before live DSP operations; preflight options get real `dspProviderReady`/`jackProviderReady` values.
3. **UI**: Settings dialog gains a "Providers" section with DSP and JACK cards (text/number/select inputs bound to the service, helper captions from the old `dspProviderSettingsMessage`/`jackProviderSettingsMessage` copy). Desktop-only note in browser preview is unnecessary (settings are localStorage) but live effects need the shell.
4. **Docs**: update the two "does not expose ... provider settings yet (documented gap)" passages in `apps/docs/docs/guide/start-on-boot.md` and `apps/docs/docs/guide/backends.md` to describe the restored UI; update matching needles in `scripts/verify-docs.sh` in the same commit; release-notes bullet.
