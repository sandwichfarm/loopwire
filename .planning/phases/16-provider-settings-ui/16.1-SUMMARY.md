# Summary 16.1 — Provider Settings UI (SEED-003, PROV-01..02)

## What changed

- **Service (PROV-01/02):** new `apps/desktop/src/lib/services/providerSettings.ts` — svelte stores for DSP
  (command, live|file-backed mode, timeout, frame count) and JACK (command, timeout, foreground|detached delegate
  mode, readiness delay) with the pre-rebuild validation semantics (positive/non-negative integer text), derived
  readiness flags (`dspRestoreProviderReady`, `jackRestoreProviderReady`, `jackLiveProviderReady`), helper-caption
  message stores, and localStorage persistence under the legacy keys `loopwire.dsp-restore.v1` /
  `loopwire.jack-restore.v1` (unparsable payloads removed; invalid stored fields fall back to defaults). Storage is
  an injected port with a `typeof localStorage` guard so unit tests run headless.
- **Runtime wiring:** `createRuntimeService` now takes the provider settings service. `backendCandidates` is a
  derived store that runs `withDspProviderCandidate` (priority 35, availability gated on DSP readiness, setup reason
  when blocked) over detected/fallback candidates, so editing Settings flips the picker live. Preflight options carry
  real `dspProviderReady`/`jackProviderReady` values. `createHostAdapter` passes a
  `createJackVirtualPortCommandProvider` (command, timeout, detached `--delegate-mode`/`--ready-delay-ms` args) to the
  JACK adapter when the JACK provider is live-ready. DSP operations run through
  `createDspConfigurationRuntimeAdapter` + `createDspRuntimeCommandPorts` when the provider is ready, with live
  transactions re-verifying provider `capabilities` (`supportsLiveGraph:true` plus read-source/write-output/
  verify-output/clear-output) via `verifyDspLiveProviderCapability` before host apply; the pure evaluation is exported
  as `evaluateDspLiveCapabilityResult`. `background_install` now sends the saved provider settings to the Tauri
  `manage_startup` command (already accepting them) so restore units carry `--dsp-provider-*`/`--jack-provider-*`
  flags, and enabling background restore refuses invalid saved JACK provider settings.
- **UI:** Settings gained a Providers section with DSP and JACK cards (command, mode/trust selects, numeric fields
  with `aria-invalid`, detached-only ready-delay enablement, readiness captions from the old
  `dspProviderSettingsMessage`/`jackProviderSettingsMessage` copy, ready/setup card states).
- **Docs:** start-on-boot.md and backends.md "does not expose ... provider settings yet (documented gap)" passages
  replaced with the restored Settings → Providers behavior; unreleased release-notes bullet added and the rebuild
  "removed from the UI" list no longer names provider settings; `scripts/verify-docs.sh` gained needles pinning the
  new passages in the same change.

## Verification

- `pnpm --filter @loopwire/desktop test` — PASS (91 tests; new providerSettings suite covers validation, readiness,
  legacy-key persistence/restore/removal, detached args, candidate injection; runtime suite covers DSP capability
  evaluation)
- `pnpm --filter @loopwire/desktop typecheck` — PASS (svelte-check 372 files, 0 errors/warnings)
- `pnpm verify:docs` — PASS; `bash scripts/verify-requirements.sh` — PASS
- Playwright smoke (system Chromium against `vite dev`): Providers section renders both cards; DSP backend option
  starts disabled with the setup reason, becomes selectable after entering a live command, re-blocks in file-smoke
  mode; settings persist under `loopwire.dsp-restore.v1` and restore after reload; detached mode enables the JACK
  ready-delay field.

## Deviations

- None functional. Live provider-backed host apply (real DSP provider process, JACK delegate) still needs the desktop
  shell and an operator-supplied provider; browser preview only proves candidate gating and persistence, matching the
  plan's note.

## Post-audit remediation

- 2026-07-11: `pnpm e2e:shell -- --dsp-provider-smoke` now runs the real desktop shell with temporary
  `XDG_CONFIG_HOME` / `XDG_STATE_HOME`, a temp state file selecting the DSP backend, seeded source buffers, and a temp
  wrapper around the bundled `loopwire-dsp-provider` with `LOOPWIRE_DSP_PROVIDER_LIVE_SMOKE=1`. It proves the desktop
  shell, Tauri command bridge, provider `capabilities`, `read-source`, `write-output`, and `verify-output` path can
  run a provider-backed live transaction without touching the operator's saved Loopwire state or real PipeWire/JACK
  graph. This closes the desktop-shell/provider wiring proof gap; real production DSP capture/playback still requires
  a host-audio provider.
