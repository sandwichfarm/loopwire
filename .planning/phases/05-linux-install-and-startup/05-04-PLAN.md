# Phase 5 Plan: Release Workflow and Artifact Checksums

**Status:** Complete
**Requirements:** LINUX-03 support path, LINUX-04 support path, QUAL-03, QUAL-05 support path

## Goal

Create a reproducible release artifact path that the curl installer, package templates, and GitHub release workflow can
all share.

## Tasks

- [x] Add `scripts/package-release.sh` as the canonical binary tarball producer.
- [x] Add `scripts/stage-release-artifacts.sh` as the canonical release attachment staging command.
- [x] Generate `loopwire-linux-${arch}.tar.gz` artifacts that match the installer contract.
- [x] Normalize tar metadata with `SOURCE_DATE_EPOCH` for same-input reproducibility.
- [x] Update `SHA256SUMS` without duplicate entries for repeated same-arch packaging.
- [x] Add `scripts/verify-release-artifacts.sh` for local release smoke.
- [x] Add `pnpm verify:release` and include it in `pnpm check`.
- [x] Add a protected GitHub release workflow for `v*` tags and manual existing-tag dispatch.
- [x] Register Tauri bundle icons so AppImage packaging has a valid square icon.
- [x] Set `NO_STRIP=true` for Tauri bundling to avoid linuxdeploy strip failures on rolling distro ELF sections.
- [x] Document release boundaries and the Linux build baseline.

## Acceptance Criteria

1. A local binary can be packaged into the same tarball shape consumed by `scripts/install.sh`.
2. The generated artifact is reproducible for identical input.
3. `SHA256SUMS` contains the generated host architecture and a secondary architecture entry without duplicate host
   entries.
4. The installer can install from the generated local release directory and run the installed binary.
5. Release workflow publishes artifacts only from `v`-prefixed tags with `contents: write` scoped to the release job.

## Remaining Phase Work

- Add release signing or signature verification before claiming signed artifacts.
- Add a dedicated AArch64 release build lane.
- Add install/run smoke for generated AppImage, deb, and rpm artifacts.
- Run package builds from published artifacts before claiming AUR or Nix install readiness.
