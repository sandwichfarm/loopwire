## Acceptance Criteria

1. Route gain and mute can be edited from the UI and persist in configuration state.
2. Graph editing controls, backend settings, monitor visibility, diagnostics, and chrome controls are keyboard-accessible.
3. Backend jargon is not shown by default outside the diagnostics panel.
4. Custom chrome buttons invoke Tauri APIs when available and fail gracefully in browser/dev mode.
5. Visual QA screenshots pass desktop and mobile smoke checks with no horizontal overflow.

## Risks

- UI controls must not imply that host audio is already changing.
- Browser smoke for Tauri APIs must not fail just because the page is outside a Tauri shell.
- Mobile density needs to remain readable after adding route controls and diagnostics.
