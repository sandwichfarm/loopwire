# Plan 17.1 — End-to-End UI Harness (SEED-001, E2E-01/E2E-02)

## Context

- Read `AGENTS.md`, `.planning/seeds/SEED-001-automated-gui-e2e-tests.md`.
- Constraint: no sudo, no system package installs. `tauri-driver` requires the system `WebKitWebDriver` binary — check `command -v WebKitWebDriver` and `ls /usr/lib/webkit*` first. If absent, the REAL-shell WebDriver path is blocked on this host: implement the documented fallback and record the gap honestly.
- Fallback (acceptable per seed scope): a Playwright-driven e2e suite against the built frontend (`vite preview` of `apps/desktop/dist` or dev server on a free port; 5173 is occupied by another project — pick 5199 and pass --strictPort). Playwright is installed system-wide: `NODE_PATH=/usr/lib/node_modules node`, `require('playwright')`, chromium at `~/.cache/ms-playwright` (see AGENTS.md Playwright notes; headless works out of the box).
- Flows to cover (assert DOM state, never fake success): empty state → create device (auto-rename, default Pass-Thru graph, 2 cables) → add source from menu → cable count grows → toggle source Off (cables dimmed class) → select card → footer Delete enabled → Delete removes → Hide Monitors collapses column → reload persists state → drag-reorder sidebar rows.
- Host-apply assertions are out of scope for the browser fallback (no Tauri bridge); the suite must assert the preview-mode behavior honestly (no `loopwire` host claims).

## Tasks

1. `scripts/e2e-desktop-ui.mjs`: node script that builds the frontend (`pnpm --filter @loopwire/desktop build`), serves `dist/` (vite preview --port 5199 or a tiny static server), launches Playwright chromium headless, runs the flow assertions above, prints a pass/fail table, exits non-zero on failure. Keep it dependency-free beyond system Playwright (`NODE_PATH=/usr/lib/node_modules`).
2. Try the real-shell path first: if `WebKitWebDriver` exists and `cargo install tauri-driver` succeeds within reason, add `scripts/e2e-desktop-shell.mjs` driving the built binary via WebDriver for one smoke flow (launch, create device, assert title). If the host lacks WebKitWebDriver, skip building this and document the requirement in the script header and docs instead — do not fake it.
3. Wire `pnpm e2e:ui` script in root package.json → `node scripts/e2e-desktop-ui.mjs`. Do NOT add it to `pnpm check` (host-dependent; document as manual validation per AGENTS reproducibility rules).
4. Docs: developer guide section (apps/docs/docs/developer/architecture.md or a new short `apps/docs/docs/developer/e2e.md` + sidebar entry in `.vitepress/config.ts`) documenting the command, coverage, and the WebKitWebDriver gap. Release-notes bullet. `pnpm verify:docs` green (update script needles if touched).
