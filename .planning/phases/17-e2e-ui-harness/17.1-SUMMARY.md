# Plan 17.1 Summary — End-to-End UI Harness

**One-liner:** Shipped BOTH harness paths — a 9-flow Playwright browser suite (`pnpm e2e:ui`) plus a real-shell tauri-driver/WebKitWebDriver smoke (`pnpm e2e:shell`) — with docs, phrase-contract needles, and verify-scripts wiring.

## Which path shipped and why

Both. The plan's fallback (Playwright against the built frontend) is the primary flow-coverage suite, and the real-shell WebDriver path also shipped because this host had everything it needs:

- `command -v WebKitWebDriver` → `/usr/bin/WebKitWebDriver` (present)
- `cargo install tauri-driver --locked` → succeeded (no sudo, user-scoped `~/.cargo/bin`)
- Display session available (`WAYLAND_DISPLAY=wayland-1`)

`scripts/e2e-desktop-shell.mjs` was run against `apps/desktop/src-tauri/target/release/loopwire` and passed: window title `Loopwire`, live Tauri bridge (`window.__TAURI_INTERNALS__` present — proving real shell, not preview), and app shell DOM rendered. The script checks each host precondition and exits with an explicit refusal (never fakes a result) where one is missing, so the WebKitWebDriver gap stays honest on other hosts.

## What was built

- `scripts/e2e-desktop-ui.mjs` — builds `apps/desktop`, serves `dist/` on strict port 5199 (never kills listeners; `--port` override), launches system Playwright Chromium headless (`/usr/lib/node_modules`, `/usr/bin/chromium` fallback), asserts 9 flows, prints a pass/fail table, exits non-zero on failure. First assertion proves NO Tauri bridge exists, pinning the suite to honest preview-mode scope (no host-apply claims).
- `scripts/e2e-desktop-shell.mjs` — read-only WebDriver smoke of the real binary via tauri-driver.
- `pnpm e2e:ui` / `pnpm e2e:shell` in root package.json; deliberately NOT in `pnpm check` (host-dependent manual validation per AGENTS.md reproducibility rules).
- `scripts/verify-scripts.sh` — `node --check` for both new .mjs files.
- `apps/docs/docs/developer/e2e.md` + vitepress sidebar entry + release-notes bullet in `release-notes/unreleased.md`; `scripts/verify-docs.sh` phrase contract extended for all of it.

## Flow coverage (`pnpm e2e:ui`, all passing)

1. preview mode is honest (no Tauri bridge, no host-apply claims)
2. empty state renders with no devices
3. create device: auto-rename ("Loopwire Device 1" → "Test Rig"), default Pass-Thru graph, 2 cables, Delete disabled with no selection
4. add source from ⊕ menu (`data-item-id="browser"`): cards 2, cables 4
5. toggle source Off: pill `aria-checked=false`, card `.off`, 2 `path.cable.dimmed`
6. select card (`.card.selected`) enables footer Delete; Delete removes card, cables back to 2
7. Hide Monitors collapses monitors column (`.headers.monitors-hidden`, header gone) and Show Monitors restores
8. reload restores state from `localStorage["loopwire.state.v1"]`
9. drag-reorder swaps sidebar rows (asserted by `data-device-row` id order, pointer-event drag past the 5px threshold)

## Deviations from plan

1. **Real-shell smoke is read-only (launch + title + bridge + shell DOM), not "create device".** The plan's suggested smoke created a device; the rebuilt shell applies configuration to the live PipeWire graph and mutates the user's persisted app state on such actions, and this is a daily-driver machine. Interactive flows are fully covered by the side-effect-free browser suite; the smoke's job is proving the WebDriver channel into the *real* shell works. Documented in the script header and `developer/e2e.md`.
2. **Delete-disabled precondition moved.** Adding a source auto-selects the new endpoint (real app behavior), so "Delete disabled" is asserted right after device creation (post-`clearSelection`) instead of just before card selection.
3. **Drag-reorder asserts row-id order, not names.** The second device auto-names "Loopwire Device 1" (the pattern counter restarts once the first device is renamed), so name-based assertions were wrong; id order is exact.

## Post-audit remediation

- 2026-07-11: `scripts/e2e-desktop-shell.mjs` gained `--dsp-provider-smoke`, an opt-in real-shell transaction proof.
  It launches the Tauri binary through tauri-driver with temporary config/state directories, writes a DSP-selected
  state file, seeds source buffers, sets provider settings in the shell profile, and verifies that the bundled
  provider wrote the expected `studio/recorder` output through the Tauri command bridge. The default `pnpm e2e:shell`
  path remains read-only; `pnpm e2e:shell -- --dsp-provider-smoke` is the proof path for provider-backed shell apply
  without mutating the user's real Loopwire state or host audio graph.
