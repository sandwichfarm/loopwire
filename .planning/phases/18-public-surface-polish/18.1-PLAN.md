# Phase 18 Plan: Public Surface Polish

**Status:** Complete
**Owner:** Codex
**Issue:** https://github.com/sandwichfarm/loopwire/issues/3
**Pull request:** https://github.com/sandwichfarm/loopwire/pull/4
**Date:** 2026-08-28

## Goal

Give Loopwire a concise public entry point, a deliberately simple Astro homepage, user-first VitePress guides at
`/docs/`, and one verified static artifact that the existing Bunny delivery pipeline can publish atomically.

## Architecture Layers

- Public documentation and project metadata: README and guide content.
- Static web shell: Astro homepage and SEO/public assets.
- Documentation shell: VitePress mounted at `/docs/`.
- Delivery platform: combined artifact assembly, CI/CT checks, Bunny CD, and deployment proof.

## Scope

1. Rewrite README around name, one-line description, screenshot, installation, basic usage, and guide links.
2. Add a current first-route/basic-usage guide and cold-read the install, configurations, backends, startup, support,
   troubleshooting, and developer guides for accuracy and navigation.
3. Add a static Astro homepage at `/` with semantic metadata, canonical/Open Graph data, structured data, robots.txt,
   sitemap.xml, accessible navigation, and restrained responsive styling.
4. Configure VitePress with base `/docs/` and assemble its output beneath the Astro output at `dist/site/docs/`.
5. Retarget Bunny deployment, manifest verification, live smoke checks, and GitHub Actions to the combined artifact.
6. Add deterministic verification for output routes, SEO metadata, internal links, installer parity, and workflow
   contracts.

## Constraints

- Astro owns only the homepage/public static shell; VitePress owns docs.
- Keep the existing VitePress guide system and Bunny proof chain.
- Do not add runtime JavaScript or a new integration when static Astro pages/assets are sufficient.
- Do not claim published availability that is not proven by the current release surface.
- Preserve the unrelated `.playwright-mcp` worktree file.

## Acceptance Criteria

- README and Astro homepage both expose the requested public onboarding information without implementation-history
  sprawl.
- The production artifact has working `/`, `/docs/`, `/docs/guide/basic-usage.html`, `/robots.txt`, `/sitemap.xml`, and
  `/install.sh` surfaces.
- VitePress-generated assets and navigation remain correct under `/docs/`.
- CI validates docs/site source and production output; CT remains scheduled/manual; CD deploys only the combined
  artifact to Bunny through the protected environment.
- Full workspace validation passes after the final edit, and the implementation PR is open with live checks visible.

## Validation

- Targeted docs/site verifier and production builds.
- Local HTTP preview assertions for homepage, docs, SEO files, links, and installer parity.
- Workflow syntax/action-version validation.
- `pnpm check` after all edits.
- GitHub PR checks after push.

## Out of Scope

- Publishing a Loopwire application release.
- Changing desktop audio behavior or packaging formats.
- Running live host-audio mutation.
- Creating or modifying Bunny secrets.
