## Tasks

1. **Core**: add optional `kind?: "app" | "capture" | "system" | "pass-thru"` to `AudioEndpoint` (types.ts). Persist/parse it in persistence.ts exactly like the other optional endpoint fields (schema stays v2 — new optional field, tolerated by v1/v2 parse; add a round-trip test in `packages/core/tests/device-controls.test.ts`). Thread `kind` through `AddInputSourceInput`/`addInputSourceToConfiguration` and `AddMonitorInput`/`addMonitorToConfiguration` (monitors may stay kindless).
2. **audio-host**: extend `AudioInputSource` with optional `kind?: "app" | "capture" | "system"` populated where enumeration knows it (PipeWire/PulseAudio: app streams → "app"; ALSA capture / `alsa_input.*` device names → "capture"). Be conservative: only set kind when the probe actually distinguishes it; otherwise leave undefined. Update detector tests if shapes are asserted.
3. **Desktop**: `hostCatalog.ts` maps enumeration kind → catalog entries (`kind` field; category names derive from kind). `deviceStore.createDevice` stamps the default source with `kind: "pass-thru"`; `addSource` passes candidate kind through. UI: `DeviceCanvas.sourceIcon`/`isAppSource` and `AppShell.sidebarSourceIcon` prefer `endpoint.kind` and fall back to the existing regex heuristics only when kind is undefined (legacy states). Menu icon per entry kind.
4. **Docs**: one line in `apps/docs/docs/guide/configurations.md` (sources carry a kind) and a release-notes bullet in `apps/docs/docs/release-notes/unreleased.md`. Run `pnpm verify:docs`; if a phrase assertion breaks, update `scripts/verify-docs.sh` in the same commit.
