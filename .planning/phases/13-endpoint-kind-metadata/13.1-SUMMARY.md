# Plan 13.1 Summary — Endpoint Kind Metadata (SEED-005, META-01/META-02)

**One-liner:** AudioEndpoint now carries an optional `kind` ("app" | "capture" | "system" | "pass-thru") populated by host enumeration, persisted in schema v2, and consumed by icons, add-menu grouping, and the mute-when-capturing option in place of label regex heuristics.

## What Changed

### Core (`packages/core`)

- `src/types.ts`: added `endpointKinds` const + `EndpointKind` type; `AudioEndpoint.kind?: EndpointKind` optional field (schema stays v2 — optional field, tolerated by v1/v2 parse).
- `src/persistence.ts`: `parseEndpoint` parses `kind` with the same optional-field spread pattern as `enabled`/`volume`; unknown values are dropped, not rejected (`parseOptionalEndpointKind`).
- `src/configuration.ts`: `AddInputSourceInput.kind` and `AddMonitorInput.kind` threaded into `addInputSourceToConfiguration` / `addMonitorToConfiguration` (monitors stay kindless in practice — no caller passes one).
- `src/index.ts`: exports `endpointKinds` and `EndpointKind`.

### audio-host (`packages/audio-host`)

- `src/types.ts`: `AudioSourceKind` ("app" | "capture" | "system") and optional `AudioInputSource.kind`, set only when the probe actually distinguishes it.
- `src/detectors.ts`:
  - PipeWire (`pw-link -o`): `capture_*` ports and `alsa_input.*`/`bluez_input.*` nodes → "capture"; `output_*` ports (app playback streams) → "app"; `monitor_*` ports stay unclassified (a sink monitor does not distinguish system audio from virtual sinks); nodes whose ports disagree stay unclassified.
  - PulseAudio (`pactl list sink-inputs`): always "app" (that probe enumerates app playback streams only).
  - ALSA (`arecord -l`): always "capture" (capture hardware only).
  - JACK: left undefined (port listings do not classify sources).

### Desktop (`apps/desktop`)

- `services/hostCatalog.ts`: `SourceCatalogEntry.kind`; category names now derive from kind (app → Running Applications, capture → Capture Devices, system → System Sources) with the old backend-based naming as fallback for unclassified sources; browser-preview samples stamped with kinds.
- `stores/deviceStore.ts`: `AddSourceInput.kind` passed through `addSource`; `createDevice` stamps the default Pass-Thru source with `kind: "pass-thru"`.
- `components/DeviceCanvas.svelte`: `sourceIcon` and a new `isAppSource(endpoint)` prefer `endpoint.kind`, falling back to the old id/label regex heuristics only when kind is undefined (legacy states); add-menu entries derive their icon from the candidate kind (`menuSourceIcon`).
- `components/AppShell.svelte`: `sidebarSourceIcon` takes the endpoint and prefers `kind` with the same legacy fallback.

### Docs

- `apps/docs/docs/guide/configurations.md`: sources carry a kind; icons/menu grouping/mute-when-capturing derive from it.
- `apps/docs/docs/release-notes/unreleased.md`: bullet under Desktop UI Rebuild.
- `scripts/verify-docs.sh`: two new phrase assertions ("Each source carries a kind", "Sources now carry a kind") locking the new doc lines.

### Tests Added

- `packages/core/tests/device-controls.test.ts`: kind round-trip through serialize/restore (stamped, unstamped, and mixed inputs) + unknown-kind values dropped without rejecting the state.
- `apps/desktop/src/lib/stores/deviceStore.test.ts`: default Pass-Thru source gets `kind: "pass-thru"`; `addSource` carries the candidate kind onto the endpoint.
- `packages/audio-host/tests/detectors.test.ts`: PipeWire/PulseAudio/ALSA enumeration fixtures updated for the new `kind` field.

## Deviations

- Added two phrase assertions to `scripts/verify-docs.sh` for the new doc lines. No existing needle broke; the additions extend the phrase contract in the established style rather than being strictly required by the plan.
- PipeWire "app" classification uses the port-name prefix (`output_*` vs `capture_*` vs `monitor_*`) rather than only node-name prefixes — this is the actual distinction `pw-link -o` exposes and keeps monitor ports conservatively unclassified.
- JACK sources stay kindless (plan permitted: only set kind when the probe distinguishes it).
- No detector emits `kind: "system"` yet; the value exists in the domain type and catalog mapping for the browser-preview sample and future probes.
