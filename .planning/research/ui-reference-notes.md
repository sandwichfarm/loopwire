# UI Reference Notes

**Date:** 2026-07-03
**Source:** User-provided screenshots of Rogue Amoeba Loopback.

These screenshots are reference material for workflow analysis only. Do not copy proprietary pixels, icons, copy,
branding, exact layout, or trade dress into Loopwire.

## Useful Workflow Patterns

- Keep configurations/devices persistent in a left rail so switching is one click and current state is obvious.
- Use a graph workspace as the main surface, with sources on the left, outputs on the right, and visible routing lines.
- Make channel count visible at the section level and inside node cards.
- Keep add actions close to the relevant section, not in a distant global menu.
- Provide a source picker grouped by category: running apps, special/system sources, and hardware devices.
- Treat monitors as a separate section that can be hidden and shown without deleting them.
- Keep global enable/level controls visible for each configuration.

## Loopwire Design Direction

- Use these patterns, but with a distinct visual system: angular signal-studio aesthetic, amber/lime/cyan accents,
  custom Loopwire mark, and different typography/composition.
- Prefer “configuration” language over “device” where it helps Linux users understand persistence and startup apply.
- Linux-specific controls must include backend selection, native/custom chrome mode, diagnostics state, and start-on-boot
  status in later phases.
